System Architecture

Architecture Overview

The Library Management System follows a layered architecture pattern, which is a common approach in Spring Boot applications. Think of it as a multi-story building where each floor has a specific purpose and communicates with the floors above and below it.

┌─────────────────────────────────┐
│           Presentation          │
│  (Controllers & Thymeleaf Views)│
├─────────────────────────────────┤
│         Business Logic          │
│         (Service Layer)         │
├─────────────────────────────────┤
│            Data Access          │
│     (Repositories & Entities)   │
├─────────────────────────────────┤
│          MySQL Database         │
└─────────────────────────────────┘

Application Layers

1. Presentation Layer

This is like the front desk of a library where users interact with the system. It includes:

  • Controllers: Handle user requests and responses
  • Views: The web pages users see and interact with
  • DTOs: Data Transfer Objects that carry data between processes

Example Controller:


@Controller
@RequestMapping("/books")
public class BookController {
    @GetMapping
    public String listBooks(Model model) {
        // Handle request and return view
    }
}

2. Business Logic Layer

This is like the librarian who knows all the rules and procedures. It contains:

  • Services: Classes that implement business logic and rules
  • Validation: Ensures data meets business requirements
  • Exception Handling: Manages errors and special cases

3. Data Access Layer

This is like the library's catalog system and storage room. It includes:

  • Repositories: Interfaces for database operations
  • Entities: Java classes that map to database tables
  • Data Mapping: Converts between Java objects and database records

Core Components

Data Flow

Request Flow

When a user interacts with the system, here's what happens:

  1. User sends request (e.g., searching for a book)
  2. Controller receives the request
  3. Service layer processes the request
  4. Repository fetches/updates data in database
  5. Response flows back through the layers
  6. View is rendered with the results
User Request → Controller → Service → Repository → Database
     ↑           ↑           ↑          ↑            ↓
Response   ←   View    ←   DTO    ←    Entity    ←  Data

Security Layers

  • Session Management: Handles user sessions
